**Repository guidance**

- Read `../AGENTS.md`, when present, for shared coding preferences. Repository-specific instructions take precedence over those shared defaults.
- For Rust backend work, read `src-tauri/AGENTS.md` before making changes. Also apply its compatibility and verification rules to frontend or CI edits made as part of that backend work.
- Follow the current user request. A roadmap or request to improve these instructions does not itself authorize implementing a refactor. Once implementation is requested, carry out its authorized scope without asking again for routine implementation choices.
- Inspect the working tree before editing. Preserve unrelated staged, unstaged, and untracked changes; do not reset or reformat another contributor's work.
- Do not stage, unstage, or commit any changes, including your own, unless the user explicitly requests that Git action. A request to edit code or fix an issue does not authorize staging, unstaging, or committing.
- Do not add `Co-authored-by` trailers, AI/agent credits, or generated-by attribution to suggested commit messages or actual commits unless the user explicitly requests that attribution. Asking for a commit message authorizes drafting text only, not staging or committing.
- Keep generated bindings and procedure inventory in sync. Any change to the Rust IPC contract (adding, renaming, moving, or removing procedures or arguments) requires two steps: update `src-tauri/tests/fixtures/ipc-inventory.json` to reflect the procedures, paths, and arguments, and regenerate `src/bindings.ts` via `cargo test --lib --locked ipc_contract::export_bindings -- --ignored --exact` along with affected TypeScript callers; do not hand-edit `src/bindings.ts`.
- Avoid returning inline `.find(...) ?? fallback` expressions; bind the lookup result to a named `const` first (e.g. `const found = ...`), then `return found ?? fallback`.
- For Zustand stores, group multi-field reads in a component with `useShallow` (`zustand/react/shallow`) instead of repeating separate hook calls, and extract reusable store selectors/helpers (e.g. `selectActiveAccount`, `selectInstanceById`, `selectSelectedInstance`, `selectProcessByName`) when derived lookups are shared across components.
- Prefer early returns (`if (...) { return ... }`) over ternary returns (`return cond ? ... : ...`), especially when transforming items in `.map` or state updaters (e.g. `if (mod.id !== id) { return mod }`, then `return { ...mod, enabled: !mod.enabled }`). Keep short returned objects single-line when clear, and wrap long returned objects with each property on its own line.
- Use `cn` from `@/shared/lib/utils` when combining or conditionally applying CSS `className` values instead of template-literal interpolation (`className={\`... ${...}\`}`) or string concatenation.
- Extract multi-line derived array transformations (e.g. `.map(...)`, `.filter(...)`) into a named `const` before passing them to constructors (`new Set(names)`), chaining another pass, or constructing returned objects (`return { items }`).
- Keep these instructions concise and update stale guidance when the implementation changes.
